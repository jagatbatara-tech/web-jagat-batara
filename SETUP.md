# SETUP.md — Subscriptions, Comments & Search

This document covers the one-time, manual setup needed to make the
**subscription**, **comment approval**, and **search** features fully
operational. All three features are built using GitHub's own
infrastructure — **no server, hosting account, or third-party service is
required.** The trade-off: subscribers need a free GitHub account.

## 1. Search

Nothing to configure. Search is 100% client-side (see `assets/search-index.js`
and `assets/site-widgets.js`): it reads articles straight from the GitHub API
(the same way the article pages already do) and lets visitors filter by
title, summary, tags, and body text. A "Cari / Search" button appears in the
navbar on every page (or press `Ctrl/Cmd+K`).

## 2. Subscriptions + "new article" notifications (GitHub Discussions)

New articles are announced as posts in this repo's **Discussions** tab
(Announcements category). Visitors "Watch" the repo's Discussions to get a
GitHub notification/email whenever a new one is posted — this is GitHub's
built-in equivalent of a newsletter, so nothing outside GitHub is needed.

Steps:
1. Enable Discussions: repo **Settings → General → Features → Discussions**.
   GitHub creates a default "Announcements" category automatically; keep
   that name (or set `DISCUSSION_CATEGORY_NAME` env var in
   `.github/workflows/notify-discussions.yml` if you rename it).
2. That's it — `.github/workflows/notify-discussions.yml` runs
   `scripts/notify-discussions.js` on every push that adds a new article
   markdown file, and posts a Discussion (title = article title, body =
   summary + link) automatically using the workflow's built-in
   `GITHUB_TOKEN` (no secrets to create).
3. The subscribe box on every page (`assets/site-widgets.js`) links visitors
   to `https://github.com/jagatbatara-tech/web-jagat-batara/discussions` and
   explains: click **Watch → Custom → check "Discussions" → Apply**. This
   requires the visitor to have (or create) a free GitHub account.
4. `feed.xml` (generated by `scripts/generate-feed.js` /
   `.github/workflows/generate-feed.yml`) is kept as a general-purpose RSS
   feed for any RSS reader, but is no longer required for notifications.

## 3. Comments (with required approval + subscriber check)

Comments are submitted via [Staticman](https://staticman.net), which turns
every comment into a **pull request** against this repo — nothing is
published until you merge it, which is the "approval dari saya" step.

Steps:
1. Register this repository with the public Staticman API (follow
   https://staticman.net/docs/, or self-host your own instance for full
   control) using `staticman.yml` in this repo as the entry config.
2. Install the Staticman GitHub App on `jagatbatara-tech/web-jagat-batara`
   so it has permission to open pull requests.
3. If you self-host Staticman instead of using the public API, update
   `STATICMAN_ENDPOINT` in `assets/comments.js` to point at your instance.
4. Update `allowedOrigins` in `staticman.yml` to match your site's real
   domain.
5. **Approval workflow**: when a comment PR appears, it includes the
   commenter's name, GitHub username, and message.
   - **Important limitation**: GitHub does not expose a public list of who
     is watching/subscribed to a repo's Discussions, so there is no API call
     that can automatically verify the "must be subscribed to comment"
     rule. Treat the commenter's checkbox confirmation as a trust-based
     attestation; if you want stronger verification, ask the commenter to
     first post a reply in the Announcements discussion (which you *can*
     see) before merging their comment PR.
   - Merge the PR to publish the comment, or close it to reject.
   - Once merged, the comment file lives under `comments/<collection>/<slug>/`
     and is automatically rendered on the article page (approved comments
     are read directly from the repo's `main` branch, so anything not yet
     merged is never shown publicly).
